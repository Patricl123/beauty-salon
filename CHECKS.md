## Что проверяет новая защита

Отсутствующий/неверный/повторно использованный CAPTCHA-токен отклоняется. Проверяются hostname, action и время выдачи. Ошибка Siteverify или хранилища квот закрывает операцию. Неожиданные ошибки базы и провайдера не раскрываются посетителю.

Несколько экземпляров HTTP-обработчика используют одну таблицу счётчиков PostgreSQL. Поддельные IP-заголовки не меняют квоту. Проверяются общие лимиты, попытки на телефон, чтение неверных кодов, перенос и отмена. Ошибки CAPTCHA и откаты бизнес-транзакций не возвращают уже потраченную попытку. Возвращаются 429 и Retry-After.

Anon и обычный authenticated-пользователь не могут обойти защиту прямыми RPC, включая служебные gateway-функции и чтение свободного времени. Закрытая таблица счётчиков недоступна API-пользователям. Назначенный администратор может создавать, переносить, подтверждать и отменять записи без CAPTCHA; роль проверяется базой.

Сохранены создание с серверной ценой, чтение по коду, пересечения, атомарный перенос, версии и идемпотентность. Браузерный тест имитирует потерю успешного ответа: повтор с новым CAPTCHA и прежним ключом запроса возвращает одну запись. Проверяется сохранение административной правки услуги после перезагрузки.

Отдельный тест создаёт запись на миграциях 001–004, применяет только 005 и проверяет сохранность существующей записи, её персонального кода и назначения администратора.

## Изоляция проверок

SQL/RLS/ограничения исполняются в одноразовом PostgreSQL/PGlite с btree_gist. Прежние 18 SQL-тестов проверяют бизнес-правила исходных миграций; новые тесты и браузерный API применяют все пять миграций.

HTTP-обработчик Edge Function в тестах тот же, что развёртывается. Только внешний ответ Cloudflare и протокол Supabase Auth заменены тестовыми. Производственный код не содержит режима пропуска CAPTCHA.

Демосервер работает на 5174, серверный тестовый сайт — на 5175, API — на 54329. Тесты не используют адреса/ключи рабочего Supabase из `.env.local`. Скриншоты и трассировки содержат только тестовые контакты, находятся в `test-results/` и исключены из Git.

## Что остаётся проверить вручную

По вашему сообщению настоящий Supabase уже подключён, а вход и операции записи прошли ручную проверку **до этого обновления**. В рамках новой задачи рабочая база, серверные секреты и развёрнутые функции не изменялись; сайт не публиковался.

Новая миграция, Edge Function и настоящий Turnstile ещё должны быть установлены и проверены по [PROTECTION_SETUP.md](PROTECTION_SETUP.md).

PGlite использует одно соединение. Для реальных гонок разных соединений обновлён `npm.cmd run test:db:live`: пересечения, дубли, версии и общий лимит. Нужны пустая одноразовая PostgreSQL-база и явный флаг разрешения. Этот тест здесь не запускался. Его тест квоты рассчитан на запросы в одном минутном окне; пересечение границы окна сообщается как неуспех с пояснением.

Отдельно не проверялись реальный сетевой DDoS, поведение Cloudflare на устройствах клиентов, Safari и реальные мобильные устройства. Ограничения общей квоты, отсутствие подтверждения телефона и возможность исчерпания лимита атакующим описаны в инструкции.
