# AURA Beauty Bishkek

Сайт салона красоты на React 19, TypeScript, Vite, Tailwind CSS 4 и React Router. Интерфейс на русском, цены в сомах, расписание в `Asia/Bishkek` (UTC+6). Поддерживаются изолированная демоверсия и серверный режим Supabase/PostgreSQL.

## Подключение Supabase

Удаление и архив мастеров/услуг: **[ARCHIVE_SETUP.md](ARCHIVE_SETUP.md)** — новые миграции `007` (активный администратор медиа) и `008` (архив, восстановление, безопасное удаление). Применяются после `001`–`006` без сброса данных.

Управление фотографиями из админ-панели: **[MEDIA_SETUP.md](MEDIA_SETUP.md)** — новая миграция `006`, приватный Storage bucket, серверная обработка `site-media`, развёртывание и проверки. Уже работающая защита записи сохраняется.

Если база уже подключена, следующая установка — **[Turnstile и серверные лимиты](PROTECTION_SETUP.md)**. Подготовлены Edge Function `booking-gateway` и отдельная миграция 005. Исходные миграции и данные сохраняются; `.env.local` нужно дополнить только публичным Site key. До установки функции и миграции новый публичный интерфейс не обращается к старым незащищённым RPC.

Подробная инструкция с конкретными действиями в Dashboard: **[SUPABASE_SETUP.md](SUPABASE_SETUP.md)**. Она описывает применение четырёх SQL-миграций, запрет публичной регистрации, создание администратора и настройку `.env.local` из безопасного [.env.example](.env.example).

Серверный режим включает создание, перенос и отмену записей в транзакциях; ограничение пересечений PostgreSQL; идемпотентность при повторной отправке; проверку версий; настоящий вход через Supabase Auth и RLS. Администраторов назначает только владелец базы. Клиент управляет своей записью по случайному персональному коду, а не по телефону.

Без конфигурации окружения сохраняется прежний **деморежим**. При `VITE_DATA_SOURCE=supabase` приложение не использует localStorage для бизнес-данных и не подменяет ошибки сервера демоданными. Облачный проект необходимо подключить самостоятельно по инструкции; реальные секреты в репозитории отсутствуют.

## Запуск

Менеджер пакетов — npm, версии зависимостей закреплены в `package-lock.json`. Используйте Node.js 24 (проверено на 24.13.0; версия указана в `.nvmrc`). Также поддерживается Node.js 22.12+. Откройте терминал в этой папке:

```powershell
npm.cmd ci
npm.cmd run dev
```

Откройте **http://127.0.0.1:5173**. Если этот порт занят, Vite выведет другой адрес в терминале.

- `/` — сайт салона и пошаговая запись.
- `/bookings` — собственные записи по персональному коду в Supabase; локальные записи посетителя в деморежиме.
- `/admin` — панель управления: в деморежиме вход без пароля, в Supabase — email/пароль заранее назначенного администратора.

В PowerShell используйте `npm.cmd`, если запуск `npm.ps1` запрещён политикой Windows. На macOS и Linux — обычный `npm`. Остановить сервер: `Ctrl+C`.

## Интерфейс и деморежим

- Адаптивная главная страница: услуги по категориям, ближайшие свободные интервалы, мастера, иллюстрации портфолио с увеличением, концепция салона, явно обозначенные демоотзывы, FAQ, контакты и место для карты без фиктивной отметки.
- Пять демонстрационных мастеров, тринадцать услуг, записи разных статусов относительно текущей даты.
- Пошаговая запись: услуга → подходящий мастер или любой свободный → календарь и время → контакты и согласие → подтверждение.
- Расчёт интервалов с учётом длительности, существующих визитов, рабочего времени салона и мастера, перерывов, выходных, отпуска и блокировок. Занятые и прошедшие интервалы недоступны; при отсутствии времени можно найти следующую дату или другого мастера. Горизонт записи — 60 дней, шаг начала — 30 минут.
- Проверка имени, телефона `+996` и 9 цифр, необязательный комментарий, согласие без предварительной галочки. Для теста: `Тестовый клиент`, `+996000000001`.
- Перенос и отмена с подтверждением освобождают прежний интервал. Экспорт `.ics` содержит начало и окончание в UTC и открывается в обычном календаре.
- Обзор, календарь дня/недели с фильтром мастера, таблица записей с поиском и фильтрами, создание по телефону, контактные данные и статусы.
- Создание и редактирование мастеров, назначение услуг, графики, перерывы, отдельные выходные и отпуск; блокировка и освобождение времени.
- При изменении графика с конфликтующими записями требуется явное подтверждение. Записи сохраняются, конфликт остаётся видимым в панели до ручного исправления.
- Создание и редактирование услуг, категории, описание, цена, длительность, активность. Существующие визиты хранят снимок цены и длительности; при новом выборе услуги/времени в форме используются актуальные значения.
- Клиенты, история, внутренние заметки только в интерфейсе панели. Настройки названия, подписи, адреса, телефона, email, часов и правил отмены.
- Шаблоны SMS / WhatsApp / email, события для клиента, администратора и мастера; план напоминаний за 24 и 2 часа. Журнал показывает, кому, когда и какое сообщение **было бы** отправлено. Изменение настроек пересчитывает будущие демонапоминания. Реальной отправки и фонового планировщика нет.
- Общее хранилище для публичной части и админ-панели, сохранение после перезагрузки, синхронизация вкладок через `storage`, сброс демоданных в настройках, ошибки сохранения и пустые состояния.
- Диалоги с нативным удержанием фокуса, закрытие Escape, видимый фокус, подписи полей, ссылка пропуска навигации, поддержка reduced motion, закреплённая мобильная кнопка записи.

## Проверки

```powershell
npm.cmd run build
npm.cmd test
npm.cmd run test:e2e
npm.cmd run test:cloud
```

`build` проверяет TypeScript и создаёт production-сборку в `dist/`. `test` проверяет расписание, миграции, SQL-права, серверные операции, идемпотентность и безопасную конфигурацию. `test:e2e` проверяет деморежим в установленном Google Chrome без видимого окна; `test:cloud` поднимает отдельный тестовый API с PostgreSQL/PGlite и имитацией Auth. Подключения к вашему облаку в этих тестах нет. Результаты и ограничения описаны в [CHECKS.md](CHECKS.md). При отсутствии Chrome установите браузер Playwright и уберите `channel: 'chrome'` из конфигураций.

Предпросмотр production-сборки:

```powershell
npm.cmd run build
npm.cmd run preview
```

Адрес предпросмотра: **http://127.0.0.1:4173**. При размещении `dist` на статическом хостинге настройте SPA fallback на `index.html` для `/admin` и `/bookings`.

## Структура

```text
src/
  components/       Общие элементы, запись, карточки и формы админ-панели
  pages/            Главная, мои записи, отдельная ленивая загрузка админ-панели
  data/seed.ts      Демомастера, услуги, исходные настройки, относительные даты
  lib/schedule.ts  Чистая логика расчёта свободных интервалов и конфликтов
  lib/repository.ts Единственная граница хранения — подготовлена для замены API
  lib/store.tsx    Общий React-контекст и операции записи/изменения статуса
  lib/notifications.ts  Генерация демособытий и времени напоминаний
  lib/calendar.ts  Экспорт календаря
  i18n.ts          Локаль, названия категорий/статусов/событий, форматирование
  types.ts         Модель данных
  styles.css       Tailwind и визуальные стили адаптивных интерфейсов
tests/             Браузерные сценарии Playwright
public/images/     Локальные иллюстративные фото
```

Название и контакты меняются из `/admin` → «Настройки»; начальные значения находятся в `src/data/seed.ts`. Для будущего кыргызского интерфейса предусмотрена отдельная точка локали и словарей в `src/i18n.ts`; полный перевод ещё потребует вынести оставшиеся тексты компонентов в словарь и добавить `ky-KG`.

## Границы деморежима и рабочий запуск

**Не вводите настоящие персональные данные.** Все записи, телефоны и заметки доступны пользователю браузера через localStorage и демонстрационную админ-панель. «Мои записи» — локальная демовитрина, а не авторизация. Несколько вкладок синхронизируют отображение, но localStorage не обеспечивает атомарную защиту от одновременной записи: для этого нужен сервер.

Для рабочего запуска нужно:

1. Подключить подготовленные SQL-миграции к Supabase по [инструкции](SUPABASE_SETUP.md). Серверные операции, валидация и защита пересечений реализованы.
2. Назначить администраторов в Supabase Auth и закрытом списке базы. Для клиентов реализован персональный код доступа; подтверждение телефона через SMS остаётся отдельной интеграцией.
3. SMS/WhatsApp/email-провайдеры, очередь сообщений, фоновые напоминания, повторные попытки и правдивые статусы доставки.
4. Подтверждённые сведения салона, настоящие фотографии с разрешениями, условия обслуживания и обработки данных, адрес и провайдер карты.
5. Резервное копирование, журнал действий, HTTPS, мониторинг и политика хранения/удаления данных. Платёжная интеграция — только если решите принимать предоплату.
